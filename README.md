# Parsing Site — мониторинг расстояний на карте

Программа подключается к **уже открытому** Google Chrome (протокол CDP) и периодически снимает с Leaflet-карты динамические маркеры (например `map-incident`). Для каждой пары «статичная точка — объект» считается расстояние. В режиме `latlng` это **километры** по ортодромии; они не зависят от зума и сдвига карты. Пиксельные режимы (`screen`, `map_relative`, `percent`) подходят только при фиксированном масштабе.

При живом съёме Leaflet-карты сборщик переходит на обзорный масштаб и просматривает соседнюю область только там, где у края видны инциденты. Затем он приближает найденные объекты для чтения номеров. Для маркеров `map-incident` обзорный масштаб не опускается ниже zoom 4: в сохранённом `html_test/44.html` при zoom 4 активна правая вкладка и в DOM есть 9 нужных маркеров. Число 477 относится к неактивной левой вкладке. Обход выполняется при каждом опросе, в том числе когда все маркеры исходного окна уже имеют номера. Если экземпляр `L.Map` недоступен из Vue, используются колесо и перетаскивание карты вместе с координатами из `.leaflet-proxy`. После обхода исходный центр и масштаб восстанавливаются. Найденные номера повторно используются до одной минуты при совпадении внутреннего ключа и близких координат.
Поле `scan_status` в ответе API показывает итог обхода (`complete`, `partial` либо причину, по которой обход не удался). Если номер не найден, таблица показывает «номер не определён»; внутренний ID остаётся ключом истории.

Если в настройках включено сохранение снимков карты, отдельный JPEG создаётся
для каждого увеличенного вида, на котором видны номера объектов. HTML сохраняется
один раз за обход при первом появлении номеров. Выбранный период (1, 3, 6, 12
или 24 часа) задаёт только папку `дата/начало-конец`; количество файлов в ней не
ограничено. Имя каждого файла содержит время съёмки и zoom. Обход без видимых
номеров не создаёт архивных файлов.

Статичные точки задаются вручную в настройках или в `config.toml` (предпочтительно `lat` / `lng`). Красный и жёлтый пороги окрашивают строки таблицы. Колонка **«Кр. / жёл. у точки»** показывает, сколько объектов находятся в красной и жёлтой зоне **относительно этой статичной точки** (одно и то же число во всех строках данной точки). Пример: у «Точки 1» три красных объекта — в колонке будет `кр. 3 · жёл. N`.

Веб-интерфейс: таблица, логи, перемещения, настройки и **хронология сближений**. Кнопка **«Тест HTML»** разбирает снимок `data_test/1.html` без сайта и без Chrome.

Кнопка **«Хронология»** открывает историю, накопленную во время опросов в режиме
`latlng`. На экране можно выбрать стационарный объект, период, максимальное
расстояние сближения в километрах и при необходимости отфильтровать динамический
объект по имени или номеру. Координаты обеих сторон выводятся как широта/долгота.

На обзорной карте и в карточках объектов доступен переключатель **«Карта»**:
**«Географическая · OpenStreetMap»** показывает города, дороги и местность,
**«Схема · без интернета»** использует встроенные контуры регионов. Точки,
траектории и зоны доступны в обоих режимах. Выбранный режим запоминается в браузере.
Географическая подложка загружается через интернет с OpenStreetMap; библиотека
Leaflet 1.9.4 включена в проект локально вместе с лицензией.

Переключатель **«Источник данных»** разделяет реальные и тестовые записи.
Тестовый набор содержит три стационарные точки, шесть движущихся объектов и 169
опросов за 14 дней. Кнопка **«Пересоздать тестовые данные»** генерирует его заново;
реальные опросы при этом не изменяются.

Если основная таблица работает в пиксельном режиме, но страница предоставляет
экземпляр Leaflet или параметры Web Mercator, история всё равно сохраняет
`lat/lng` и отдельное `geo_distance_km`. Пиксели переводятся по текущим центру,
масштабу и размеру карты в момент опроса; расстояние считается по haversine.

## Полный цикл работы программы

1. `main.py` передаёт аргументы в `parsing_site.runner`. Без аргументов запускается
   локальный веб-сервер на `127.0.0.1:8081`.
2. При старте веб-приложения открываются `data/tracking.db` и
   `data/table_history.db`, создаются недостающие таблицы, выполняются совместимые
   миграции старой схемы и загружаются runtime-настройки. Если их ещё нет, они
   копируются из `config.toml`.
3. Пользователь запускает Chrome с отдельным профилем и CDP-портом 9222, открывает
   карту и нажимает «Запустить». Обычный профиль Chrome приложение не изменяет.
4. `ParseWorker` создаёт один фоновый поток. Поток подключается к уже работающему
   браузеру через Playwright и выбирает вкладку, URL которой содержит значение
   поля «Сайт для парсинга».
5. Перед каждым опросом worker повторно читает runtime-настройки. Изменение сайта,
   CDP-адреса или ожидаемого селектора вызывает переподключение; прочие настройки
   применяются на следующем опросе без перезапуска потока.
6. JavaScript из `tracking.py` выполняется внутри выбранной вкладки. Он находит
   контейнер Leaflet, динамические и страничные статичные маркеры, их центры,
   размеры, цвета, CSS-смещения, текущий zoom и по возможности экземпляр `L.Map`.
7. Координаты приводятся к выбранному режиму. Для `latlng` сначала используется
   API живого Leaflet; резервный путь восстанавливает координаты из
   `.leaflet-proxy` по Web Mercator. Настроенные статичные точки объединяются с
   точками страницы согласно `static_source`.
8. Для декартова произведения «каждая статичная точка × каждый динамический
   объект» считается расстояние, присваивается статус `alert`, `warning` или `ok`,
   добавляются групповые счётчики и телефон, найденный по адресу в XLSX.
9. Нормализованный снимок сохраняется в `tracking.db`, а точная копия строк
   основной таблицы — в `table_history.db`. Последний снимок остаётся в памяти
   worker и отдаётся веб-интерфейсу через `/api/state`.
10. Браузерный JavaScript периодически запрашивает состояние, обновляет таблицу,
    логи и оценку роста БД. Worker ждёт остаток интервала с помощью прерываемого
    события, поэтому команда остановки не обязана ждать весь интервал.

Ошибки подключения или разбора не завершают веб-сервер: worker переводится в
состояние `error`, пишет сообщение в журнал и повторяет попытку через 2–10 секунд.
При остановке приложения поток завершается, после чего обе SQLite-базы закрываются.

## Архитектура и границы ответственности

Приложение состоит из четырёх слоёв:

- **Входы:** CLI в `runner.py`, HTTP API в `webapp.py`, сохранённый HTML в
  `html_probe.py` и живая вкладка через `browser.py`.
- **Предметная логика:** `coordinates.py` отвечает за системы координат и
  проекции, `tracking.py` — за маркеры, расстояния, статусы и сериализацию.
- **Оркестрация:** `worker.py` управляет циклом опроса, переподключением и
  публикацией последнего снимка; `settings_store.py` накладывает настройки UI на
  базовую TOML-конфигурацию.
- **Выходы:** `db.py` хранит нормализованную географическую историю,
  `table_history_db.py` — строки основной таблицы, `history_export.py` создаёт
  XLSX, `table_view.py` — терминальный, HTML-, CSV- и JSONL-вывод.

`parser.py` и `processor.py` представляют отдельный универсальный механизм
извлечения CSS-полей/HTML-таблиц. Он не участвует в основном цикле мониторинга
Leaflet, пока его явно не подключит вызывающий код.

## Модель одного снимка

`TrackingSnapshot` содержит:

- адрес и заголовок вкладки;
- размер окна и карты, zoom, центр и источник географических координат;
- список статичных и динамических `SceneObject`;
- строки `DistanceRow` для всех вычислимых пар;
- пороги, единицу расстояния и предупреждение о качестве масштаба.

Пара пропускается, если выбран режим `latlng`, но хотя бы одна её точка не имеет
географических координат. Поэтому число строк обычно равно
`число статичных × число динамических`, но может быть меньше при неполной географии.
Индекс динамического объекта — его порядок в текущем DOM. Если сайт меняет порядок
маркеров между опросами, история может связать один индекс с другим объектом;
стабильное имя помогает анализу, но ключом хранения остаётся индекс.

## HTTP API

Сервер слушает только loopback-интерфейс. Основные маршруты:

| Метод и путь | Назначение |
|---|---|
| `GET /api/state` | Настройки, состояние worker, последний снимок, рост БД и логи |
| `GET/PUT /api/settings` | Чтение и сохранение runtime-настроек |
| `POST /api/worker/start`, `POST /api/worker/stop` | Управление фоновым опросом |
| `GET /api/logs`, `GET /api/movements` | Журнал и последние перемещения |
| `POST /api/test-file` | Таблица по HTML строго из `data_test/` |
| `GET /api/probe` | Диагностика HTML строго из `data_test/` |
| `GET /api/history/static-objects` | Список точек, доступных в хронологии |
| `GET /api/history` | Отфильтрованные сближения и сводка |
| `GET /api/history/export.xlsx` | Та же выборка в Excel, максимум 20 000 строк |
| `GET /api/history/trajectory/{id}` | Траектория одного динамического объекта |
| `GET /api/history/static-zones/{id}` | Траектории объектов, входивших в зоны точки |
| `POST /api/history/fake/generate` | Пересоздание демонстрационной истории |
| `POST /api/beep` | Ручная проверка системного звукового сигнала |

Даты истории принимаются в ISO-формате. Дата без времени трактуется как начало
суток для `date_from` и как `23:59:59` для `date_to`. Ответы с большими выборками
ограничены 20 000 строками/точками и содержат признак `truncated`, где применимо.

## Телефоны статичных объектов

При первом расчёте строки лениво читается `addresses_updated_02.xlsx`. Обязательные
колонки — `adres` и `telephone`. Имя статичной точки сначала сравнивается с исходным
адресом, затем с нормализованным: регистр, повторные пробелы и знаки `.,;:` не
учитываются. Частичные совпадения не используются. Файл читается один раз за
процесс, а найденный телефон дополнительно кэшируется на время построения снимка.

## Надёжность и ограничения

- Chrome должен быть запущен именно с `--remote-debugging-port` и отдельным
  `--user-data-dir`; приложение не запускает и не авторизует сайт само.
- CSS-селекторы зависят от DOM целевой страницы. Изменение верстки сайта может
  привести к пустому снимку без программной ошибки.
- Пиксельные расстояния зависят от zoom, размеров окна и панорамирования. Для
  сравнимой истории используйте `latlng`.
- SQLite работает в WAL-режиме и защищён блокировками внутри процесса, но файлы БД
  не предназначены для одновременной записи другим процессом приложения.
- История не очищается автоматически. Оценка суточного роста показывается в UI;
  архивирование и политика хранения остаются обязанностью оператора.
- Web API не имеет аутентификации и рассчитан только на локальный адрес
  `127.0.0.1`. Не публикуйте порт 8081 во внешнюю сеть без отдельного reverse proxy
  с авторизацией.

## Запуск

Нужны Python 3.14+ и [uv](https://docs.astral.sh/uv/).

```powershell
uv sync
uv run python main.py
```

Интерфейс: http://127.0.0.1:8081

Вкладка **«Журнал MAX»** (`/max-logs`) показывает каждое уведомление и тестовое
сообщение: получателя, время постановки в очередь, итоговый статус и текст ошибки.
Записи можно фильтровать по статусу и MAX user ID. На этой же странице можно
ввести user ID и нажать **«Отправить тест»**. Для теста нужен настроенный токен;
включать рассылку зон и добавлять пользователя в список получателей не требуется.
Статус отправки обновляется автоматически через несколько секунд.

Другие команды:

| Команда | Назначение |
|---------|------------|
| `uv run python main.py web` | То же, что запуск без аргументов: FastAPI |
| `uv run python main.py test-server` | Тестовая SVG-карта с движущимися объектами на порту 8000 |
| `uv run python main.py chrome` | Chrome с `--remote-debugging-port=9222` и профилем `.chrome-profile` |
| `uv run python main.py check` | Проверка, что CDP отвечает |
| `uv run python main.py probe` | Таблица расстояний по `data_test/1.html` (без браузера) |
| `uv run python main.py probe --json` | Тот же файл, полный JSON-отчёт по маркерам |
| `uv run python main.py inspect` | Один снимок живой вкладки Chrome |
| `uv run python main.py run` | Цикл опроса в терминале по `config.toml` |

Опрос сайта:

1. Запустите Chrome с CDP (`main.py chrome` или `start_chrome.bat`).
2. Откройте нужную карту в **этом** окне Chrome.
3. В настройках UI укажите фрагмент URL вкладки (поле «Сайт для парсинга»).
4. Нажмите **«Запустить»**.

### Сквозная проверка на тестовой карте

1. В первом терминале запустите `uv run python main.py test-server`.
2. Запустите Chrome с CDP командой `uv run python main.py chrome` и откройте
   `http://127.0.0.1:8000` именно в этом окне Chrome.
3. Во втором терминале запустите интерфейс: `uv run python main.py web`.
4. На `http://127.0.0.1:8081` нажмите **«Запустить»**. Значение «Сайт для
   парсинга» по умолчанию уже содержит `8000`.
5. Через несколько опросов откройте **«Хронология»**, выберите источник
   «Реальные данные» и одну из контрольных точек. Там появится фактически
   накопленная траектория тестовых объектов.

Карта содержит шесть объектов со стабильными номерами и именами. Они движутся по
замкнутым маршрутам вокруг Белгорода и Курска; полный цикл занимает три минуты.
Пауза, сброс и ускорение на странице карты позволяют воспроизводить сценарии.

Проверка на тестовой странице без сайта: **«Тест HTML»** или `uv run python main.py probe`.

## Настройки

Файл `config.toml` — значения по умолчанию. После первого открытия UI настройки пишутся в SQLite (`data/tracking.db`) и перекрывают TOML, пока вы их не измените в интерфейсе.

Параметр «Точность точек на карте истории» задаёт 3–6 знаков после запятой
(по умолчанию 4). Близкие последовательные точки одной траектории объединяются
на карте с сохранением времени первой точки; исходные координаты в базе и
расчёты расстояний остаются без округления.

База использует нормализованную схему: `polls` хранит один опрос и параметры
карты, `static_observations` — одну позицию каждой стационарной точки за опрос,
`dynamic_observations` — одну позицию динамического объекта. Расстояния между
парами рассчитываются при запросе истории, поэтому одинаковая позиция объекта
не дублируется для каждой стационарной точки.

Полные строки таблицы главного экрана дополнительно сохраняются при каждом
обновлении в отдельную базу `data/table_history.db`. Таблица `table_snapshots`
фиксирует каждый снимок, включая пустой, а `table_history` содержит строки с
датой и временем, объектами, координатами, расстоянием, статусом и телефоном.
Главный экран показывает прогноз числа строк и объёма этой базы за сутки по
текущему интервалу обновления и среднему размеру последних снимков.

При обнаружении старых таблиц `distance_rows` / `movements` приложение выполняет
транзакционную миграцию настроек, опросов и стационарных объектов. Динамические
наблюдения старой схемы не переносятся, поскольку в них отсутствуют необходимые
географические данные. После проверки количества перенесённых стационарных
наблюдений старые таблицы исключаются из рабочей БД. Тяжёлое полное сжатие не
выполняется при запуске, поэтому большая БД не блокирует открытие интерфейса.
Новая динамическая история накапливается с первого опроса после запуска.

Если SQLite уже повреждена, запуск не прерывается: из неё извлекаются все ещё
читаемые настройки (включая стационарные объекты), создаётся исправная
`tracking.db`, а исходный файл сохраняется рядом как
`tracking.corrupt-ДАТА-ВРЕМЯ.db` для ручной проверки или удаления.

Важные поля `[tracking]`:

- `dynamic_selector` — CSS динамических маркеров (по умолчанию `.leaflet-marker-icon.map-incident`).
- `coordinate_mode` — `latlng` (км), `map_relative` / `percent` / `screen` (px).
- `threshold` / `warning_distance` — красный и жёлтый порог (км в `latlng`, иначе px).
- `[[tracking.static_objects]]` — точки: `lat`/`lng` и/или `x`/`y`.

В `latlng` канонические координаты — географические. При зуме и панорамировании пиксели `x`/`y` пересчитываются, километры остаются.

## Как считаются координаты

В HTML маркера обычно только `transform: translate3d(...)` — это **пиксели текущего вида**, не градусы.

1. **Живая карта.** Ищется экземпляр Leaflet (`containerPointToLatLng` / `latLngToContainerPoint`).
2. **Снимок HTML или карта без JS-объекта.** Из `.leaflet-proxy` восстанавливаются zoom и центр (EPSG:3857 / Web Mercator), пиксель переводится в lat/lng.

Расстояние в `latlng`: формула haversine, единица **км**.

## Таблица

Каждая строка — одна пара точка–объект:

| Колонка | Смысл |
|---------|--------|
| № статичного | Номер точки |
| Координаты статичного | lat/lng или x/y |
| Динамический объект | Имя/тип маркера |
| № динамического | Порядковый номер на странице |
| Координаты динамического | lat/lng или x/y |
| Расстояние | км или px |
| **Кр. / жёл. у точки** | Сколько объектов красные и жёлтые **до этой точки** |
| Статус | близко / внимание / норма |

Цвет строки задаётся дистанцией этой пары. Счётчики в колонке «Кр. / жёл.» относятся ко **всем** объектам относительно той же точки, не только к текущей строке.

## Оповещения MAX

В «Настройках» включите рассылку, введите токен бота MAX и добавьте группу получателей. В одном поле можно указать несколько `user_id` через пробел или запятую. Для группы выберите «Все объекты» и общие зоны либо добавляйте стационарные объекты по одному из списка с собственными зонами. Выбранный объект исчезает из вариантов других строк этой группы. При входе динамического объекта в выбранную зону отправляется сообщение с его номером, расстояниями до выбранных точек и ближайшей точкой. Повторные опросы в той же зоне сообщений не создают; после выхода из зоны новый вход создаст новое сообщение.

К сообщению прикладывается ближайший по времени JPEG, на котором виден номер динамического объекта. Снимки создаются при приближении карты и появлении номеров. Даже если обычный архив снимков отключён, при включённой рассылке JPEG сохраняются в `data/max_bot_screenshots/`; размер задают настройки снимка. Если подходящего кадра нет, сообщение отправляется с пометкой об этом. Первый опрос отправляет найденные объекты в выбранных зонах; следующие опросы отправляют только новые входы в зоны. Если один динамический объект вошёл в зоны нескольких выбранных стационарных точек, получатель получает одно сообщение с перечнем точек. Очередь ограничивает скорость отправки; при ответе MAX о превышении частоты запрос повторяется с задержкой. Состояние рассылки, первый опрос и ошибки доставки видны в логах приложения.

Токен можно ввести в настройках или задать как `MAX_BOT_TOKEN` в окружении либо в `.env` рядом с приложением (рядом с exe при сборке). Для текущей структуры проектов читается и `../MAX_BOT/.env`. Токен из `.env` не копируется в SQLite; API настроек возвращает только признак его наличия. После выбора получателей и зон включите галочку рассылки. Набор доверенных CA упакован внутрь exe: файл можно переносить без отдельной папки сертификатов. Если в сети используется собственный центр сертификации, его доверенный набор можно положить в `certs/ca-bundle.pem` рядом с exe. Проверка TLS не отключается.

Для отправки бот должен иметь доступ к личному диалогу с получателем. Первую живую отправку можно проверить после сохранения токена и запуска опроса карты.

## Каталоги данных

- `data_test/` — сохранённые страницы для проверки (например `1.html`).
- `data/` — БД `tracking.db` и `table_history.db`, при `inspect`/`run` также `distances.html`, `distances.csv`, история JSONL.
- `.chrome-profile/` — профиль Chrome для CDP (не коммитить).

## Сборка exe

В проекте есть PyInstaller (`parsing_site.spec`). Рядом с exe копируются `config.toml` и скрипты запуска Chrome. Веб-ресурсы упакованы в bundle (`web/`).
